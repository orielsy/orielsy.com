## The Context Pollution Problem

As context windows expand, the naive approach is to dump entire repositories, test logs, and chat histories into an agent's prompt.

More context does not automatically produce better code. Large undifferentiated context sets can introduce several failure modes:
1. **Context degradation**: Critical architecture rules can get lost in irrelevant file noise.
2. **Attention dilution**: Agents may surface deprecated conventions present in legacy files.
3. **High latency & compute cost**: Repeatedly sending large token payloads can degrade developer feedback loops.

```text
Naive Prompting:
[Entire Codebase] ---> [Agent LLM] ---> (Large, Noisy Context)

Context Engineered Pipeline:
[Repository State] ---> [Structured Repository Knowledge]
                             |
                             v
               [Model Context Protocol (MCP) Server]
                             |
                 (Targeted Tool & Rule Dispatch)
                             v
                        [Agent LLM] ---> (Task-Relevant Context)
```

## Architectural Pillars of Effective Context Engineering

### 1. Hierarchical Rule Granularity
Instead of a single monolithic prompt, structure rules hierarchically:
- **Global Invariants**: Core language version, forbidden libraries, formatting rules.
- **Package / Domain Boundaries**: Service-specific error types, authentication guards.
- **Component Primitives**: Component contracts, state-management rules, and UI conventions.

### 2. Just-In-Time Tool Retrieval via MCP
Using the **Model Context Protocol (MCP)**, an agent can query specialized tools and resources only when a task demands them. Conceptual examples include:
- `get_component_schema`: Return typed prop interfaces without loading an entire component implementation.
- `search_architectural_decisions`: Fetch ADRs relevant to the area being modified.

<Callout type="architecture" title="PERSISTENT KNOWLEDGE OVER PROMPT REPETITION">
  Moving engineering context from ephemeral user prompts into persistent, version-controlled repository artifacts can improve architectural consistency across different developer sessions.
</Callout>
