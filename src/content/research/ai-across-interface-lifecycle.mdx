AI can participate in an interface long before and long after a user interacts with it. During development, coding agents can consume specifications, product knowledge, component contracts, and existing implementation context to help create or modify UI. During build and preparation stages, the same knowledge can be structured for machine use. At runtime, intelligent capabilities can interpret intent, retrieve relevant knowledge, transform data, or adapt guidance. This exploration maps those stages and asks which sources of truth should remain shared—and which responsibilities should remain deliberately separate.

## Planned Scope

This is an umbrella exploration connecting four layers without collapsing them into one system:

- **Development-time AI** — coding agents, durable project memory, and context engineering.
- **Preparation/build-time knowledge work** — structured product knowledge, indexing, and machine-readable context.
- **Runtime AI** — adaptive UX and non-chat interface capabilities.
- **Execution layer** — browser-local, machine-local, server, edge, or cloud inference runtimes.

The article remains a placeholder until those relationships can be developed without duplicating the more focused Research pieces that already own each area.
