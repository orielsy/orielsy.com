## The Challenge: Real-Time Audio at the Interface Layer

Building a real-time, on-device speech-to-text interface presents a classic distributed systems challenge disguised as a frontend feature. 

Unlike batch transcription—where a static media file is uploaded, processed sequentially, and returned as a finished transcript—real-time live streaming requires continuous, low-latency coordination across four distinct operational domains:

1. **Hardware Audio Capture**: Sampling continuous analog microphone signals in the browser/client environment.
2. **Temporal Buffer Windowing**: Deciding when to cut an audio stream into discrete chunks for neural processing.
3. **Acoustic Gating & Silence Detection**: Applying optional voice-activity detection to reduce decoder hallucinations during natural pauses in human speech.
4. **Responsive UI Compositing**: Coordinating animated overlay graphics with audio and inference work.

## 1. The Audio Sample Rate Dilemma

Consumer audio interfaces can provide higher-rate stereo buffers than the 16 kHz mono PCM contract used by the companion API.

Feeding higher-rate stereo streams directly over a network or local IPC socket introduces several penalties:
- **Bandwidth Waste**: Higher-rate stereo PCM increases payload size compared with a normalized mono stream.
- **Garbage Collection Pressure**: Continual instantiation of large `Float32Array` objects triggers micro-pauses in the JavaScript runtime.
- **Model Input Mismatch**: The companion API expects **16,000 Hz 16-bit mono PCM**, so capture data should be normalized before transmission.

### Normalizing the Client Audio Contract

An audio capture pipeline can downsample on the capture thread before packet transmission:

```javascript
// High-efficiency downsampler: AudioContext rate -> 16,000 Hz Int16 PCM
function downsampleBuffer(buffer, inputSampleRate, outputSampleRate = 16000) {
  if (inputSampleRate === outputSampleRate) return buffer;
  
  const sampleRateRatio = inputSampleRate / outputSampleRate;
  const newLength = Math.round(buffer.length / sampleRateRatio);
  const result = new Float32Array(newLength);
  
  let offsetResult = 0;
  let offsetBuffer = 0;
  
  while (offsetResult < result.length) {
    const nextOffsetBuffer = Math.round((offsetResult + 1) * sampleRateRatio);
    let accum = 0, count = 0;
    
    for (let i = offsetBuffer; i < nextOffsetBuffer && i < buffer.length; i++) {
      accum += buffer[i];
      count++;
    }
    result[offsetResult] = count > 0 ? accum / count : 0;
    offsetResult++;
    offsetBuffer = nextOffsetBuffer;
  }
  return result;
}
```

The normalized float array can then be clamped and converted to signed 16-bit integers (`Int16Array`). This reduces raw PCM size relative to higher-rate stereo capture, while actual network throughput also depends on WebSocket framing and transport behavior.

## 2. Temporal Windowing: Latency vs. Semantic Context

Acoustic transformer decoders do not evaluate isolated phonemes; they require context windows to resolve homophones, linguistic cadence, and grammatical structure. Window duration therefore creates a trade-off: shorter windows can reduce waiting time but provide less context, while longer windows can improve context at the cost of responsiveness. The companion API defaults `chunk_length_seconds` to `3`, which is a configuration default rather than a measured optimum.

In `fastapi_app.py`, the server implements a **sliding chunk accumulator**:

```python
chunk_length_bytes = int(client.config.get("chunk_length_seconds", 3)) * client.sampling_rate * client.samples_width

if len(client.buffer) >= chunk_length_bytes:
    client.scratch_buffer.extend(client.buffer)
    client.buffer.clear()
    asyncio.create_task(self.process_buffer(client, websocket))
```

## 3. Combating Ghost Hallucinations in Live Audio

One of the most notorious challenges when deploying autoregressive speech models (like Whisper) on continuous microphone streams is **ghost hallucination during silence**.

When fed ambient room noise, HVAC hum, or silence, Whisper’s decoder attempts to predict text from unconditioned acoustic tokens. This frequently results in phantom outputs:
- Infinite loops: *"Thank you. Thank you. Thank you."*
- Subtitle artifacts: *"[Music]", "[Applause]", "Subscribe to the channel."*
- Punctuation cascades: *". . . . ."*

The intended pipeline uses **Two-Stage Defense Gating** to reduce hallucinated output:

### Layer 1: Backend Voice Activity Gating (PyAnnote VAD)
The companion API includes a PyAnnote VAD implementation that can analyze a scratch buffer and return speech segments. In the current `ConnectionManager.handle_audio_chunk` path, chunks are accumulated directly and `get_vad()` is not invoked, so VAD should be treated as available support rather than a verified active gate for every stream.

### Layer 2: Client-Side Probabilistic Filtering
The current API returns Whisper's segment metadata to the client. The available companion source does not contain a client-side `no_speech_prob` or temperature filter, so this article does not claim those thresholds or an elimination guarantee as part of the verified pipeline.

## 4. Multi-Process Compositing & UI Thread Isolation

In broadcast environments, rendering responsiveness matters. An animated lower-third that stutters or competes with audio and inference work can make a production feel less polished.

To protect UI performance:

1. **Async Worker Offloading**: `fastapi_app.py` executes `model.transcribe()` inside `asyncio.to_thread()`, which helps keep the Python event loop available for WebSocket handling.
2. **Client Layout and Compositing**: Techniques such as `getBoundingClientRect`, `requestAnimationFrame`, and CSS transforms can help coordinate overlay updates, but the available API repository contains no client source or recorded frame-time/GPU measurements to verify a particular implementation or performance result.

## 5. Architectural Takeaways & Future Directions

Building on-device intelligent UI systems reveals several core principles:

1. **Single-Purpose Neural Models for Primitives**: Dedicated STT models such as Whisper provide a focused transcription component without requiring a general-purpose conversational model.
2. **Tiered Edge Intelligence**: In-browser runtimes (WebLLM / WebGPU) can be layered downstream of the caption stream to support local translation, topic extraction, and meeting summarization without per-request cloud inference costs for suitable workloads.
3. **Decoupled Architecture as a Prerequisite**: Isolating audio capture, neural inference, and UI rendering into independent processes can help preserve responsiveness.
