The Adaptive Enterprise UI Lab is a shared reference application for testing how product knowledge can participate in an enterprise interface without displacing deterministic application truth. It grows out of [Progressive Enhancement for Intelligent Interfaces](/research/progressive-enhancement-intelligent-interfaces) and provides the working implementation behind [Documentation-Driven Adaptive UX](/research/documentation-driven-adaptive-ux).

Phase 1 is implemented today. Later phases are intentionally separated so selective inference and runtime placement can be added without rewriting the deterministic core.

## Architecture at a Glance

The current implementation deliberately keeps application truth, authored knowledge, response policy, and rendering as separate concerns.

## What Phase 1 Demonstrates

The working instrument uses a focused Data Connection scenario built around:

- application/domain state
- deterministic validation
- authored product knowledge
- product/runtime context
- user familiarity
- deterministic knowledge applicability
- response policy
- adaptive UI rendering
- an inspectable decision trace

The resolver keeps application truth authoritative. Several compatible Data Connections permit guidance but not guessing; exactly one compatible option can support a user-accepted preconfiguration offer.

That gives the project an inspectable deterministic baseline: state, validation, authored knowledge, familiarity, applicability, and response policy are all visible before selective inference is introduced.

## Next · Selective Inference

The next extension is the smallest inference capability that can add value to the existing Data Connection scenario: **natural-language intent / question mapping**.

A question such as “Why can't this workflow connect anymore?” could produce candidate product-knowledge concepts. Those candidates would still pass deterministic applicability filtering and be reconciled against the actual configuration, product version, available options, validation state, and approved product knowledge before response policy determines what the interface should show.

Conceptually:

```text
user question
      ↓
intent / concept interpretation
      ↓
candidate product-knowledge concepts
      ↓
deterministic applicability filtering
      ↓
application-state reconciliation
      ↓
response policy
      ↓
contextual UI explanation
```

That capability is the next architectural extension; it is not part of the current Phase 1 source. The existing lab remains fully useful without it.

## Later · Runtime Placement

Once selective inference is useful, a later phase can evaluate where it should run across browser-local, machine-local, server, edge, or cloud tiers, using capability detection, fallback, and runtime instrumentation. Technologies such as WebLLM would enter at that execution-layer stage based on demonstrated need.

Phase 1 therefore remains the current implementation evidence; the later phases define how the lab can grow without collapsing product truth into the inference layer.
