## Intended Direction

The concept is a local service based on the **Model Context Protocol (MCP)** that would let a coding agent request repository-specific context on demand instead of repeatedly loading large portions of a codebase into its prompt.

```text
+---------------------+        MCP JSON-RPC        +------------------------+
| Coding Agent Client | <------------------------> | Proposed Context       |
|                     |                            | Service                |
+---------------------+                            +------------------------+
                                                               |
                                         +---------------------+---------------------+
                                         |                                           |
                                         v                                           v
                              +--------------------+                      +--------------------+
                              | Structured Code /  |                      | Architecture ADR   |
                              | Interface Context  |                      | & Rule Retrieval   |
                              +--------------------+                      +--------------------+
```

---

## Capabilities Being Explored

### 1. Focused Interface Inspection
A future prototype could expose a tool that returns only the interface information relevant to a task—for example exported TypeScript types or component contracts—without forcing an agent to read an entire implementation file.

### 2. Architectural Constraint Retrieval
Another direction is to let an agent retrieve repository rules or ADRs relevant to the code it is changing before proposing an edit.

These are intended capabilities, not claims about a finished system.

---

## Candidate Technical Direction

- **Protocol Runtime**: Model Context Protocol using a TypeScript/Node.js service.
- **Repository Analysis**: Exploring structured parsing or indexing approaches where they materially improve retrieval.
- **Storage / Search**: Not yet established. No database, vector index, or semantic-graph implementation should be assumed from this concept entry.
