## Project Overview

**speechBubbles** is an on-device desktop overlay and live-broadcast graphics platform designed to bring television-style dynamic graphics and automated speech transcription to streamers, presenters, and video creators without relying on cloud transcription APIs.

The system is structured as two decoupled tiers:

1. **The Desktop Overlay Client (`speechBubbles`)**: An Electron and Vue 3 application that generates frameless, transparent broadcast graphics—including animated speaker lower-thirds, title banners, topic tickers, and speech bubble captions. Broadcasters capture these windows directly in **OBS Studio** (or similar streaming software) using chroma-key or alpha transparency.
2. **The Local Audio & Inference Engine (`whisper-api`)**: A local Python FastAPI service that ingests real-time 16 kHz 16-bit PCM audio streams over WebSockets (`ws://localhost:8000/listen`), accumulates fixed-duration audio chunks, and runs local Whisper transcription.

## Core System Highlights

### 1. OBS-Optimized Broadcast Graphics Engine
Television news broadcasts frequently display context when a speaker is introduced—credentials, affiliation, topic titles, and disclaimers. 

`speechBubbles` translates this workflow into a dedicated operator console:
- **Lower-Third Banners (`BannerView.vue`)**: Configurable dual-tone gradient banners with entrance and exit timing queues.
- **Presenter Nametags (`TitleView.vue`)**: Dropdown title badges for displaying speaker names and professional roles.
- **Chroma-Key & Alpha Ingestion**: Windows are formatted with distinct background borders and transparent viewport layers, allowing streaming software to isolate graphics while minimizing edge artifacts.

### 2. High-Throughput 16 kHz Audio Streamer
Browser audio interfaces commonly expose 44.1 kHz or 48 kHz floating-point buffers. Sending that format directly would use substantially more bandwidth than the 16 kHz mono stream expected by this backend.

In `CaptionControl.vue`, the client downsamples audio before transmission:
- The microphone's mono `AudioContext` buffer is downsampled to a 16 kHz float stream.
- Audio samples are converted to signed 16-bit PCM integers (`convertFloat32ToInt16`) and streamed as binary WebSocket messages.

At 16 kHz × 16-bit mono, the resulting payload is approximately **32 KB/sec** before protocol overhead. That figure is derived directly from the sample format rather than measured as a performance benchmark.

### 3. Asynchronous Whisper Inference & Client Filtering
Running neural inference directly on an async event loop can stall WebSocket handling while transcription is in progress.

The current public backend and client handle that work as follows:
- Incoming PCM data is accumulated until the configured chunk threshold is reached, then moved into a scratch buffer for processing.
- `model.transcribe()` is executed with `asyncio.to_thread()`, moving blocking inference off the async event loop.
- Returned Whisper segments are filtered in `CaptionControl.vue`; segments are accepted when `no_speech_prob <= 0.6`, `temperature <= 0.8`, and non-empty text is present. This helps suppress likely hallucinated output during low-confidence segments.

The backend repository contains PyAnnote VAD scaffolding and dependencies, but the current public `process_buffer()` path does not invoke that VAD pipeline before Whisper inference.

### 4. Dynamic Bounding-Box Layout & Animation
When new transcription segments arrive from the backend, `CaptionsView.vue` computes the physical layout of active bubbles on screen:
- Using `getBoundingClientRect()`, each caption calculates its offset relative to previous elements.
- Bubble pop-in animations and vertical shifts are orchestrated using double-buffered `requestAnimationFrame` transitions.

## Technical Stack

- **Desktop Shell**: Electron with `electron-acrylic-window` transparency and `qhotkeys` system bindings.
- **Frontend Layer**: Vue 3 (Composition API / `<script setup>`), Pinia state management, and Vite.
- **Audio Capture**: Web Audio API (`AudioContext`, `createScriptProcessor` / `MediaStreamAudioSourceNode`).
- **Inference Engine**: Python, FastAPI, Uvicorn, and OpenAI Whisper. The backend also contains PyAnnote Audio VAD scaffolding, but VAD is not active in the current streaming transcription path.
- **Video Production**: OBS Studio window capture and transparent/chroma-key overlay compositing.
