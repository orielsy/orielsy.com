## Project Overview

**speechBubbles** is an on-device desktop overlay and live-broadcast graphics platform designed to bring television-style dynamic graphics and automated speech transcription to streamers, presenters, and video creators without relying on cloud transcription APIs.

The desktop graphics surface and the local transcription service remain decoupled so they can evolve independently.

## System Architecture

The working system isolates audio capture, streaming WebSocket transport, local Whisper inference, client-side transcript policy, transparent Electron rendering, and OBS Studio compositing while keeping the complete path on the broadcast workstation.

## Broadcast Graphics in Practice

Television news broadcasts frequently display context when a speaker is introduced—credentials, affiliation, topic titles, and disclaimers. `speechBubbles` translates that workflow into a dedicated operator console:

- **Lower-Third Banners (`BannerView.vue`)**: Configurable dual-tone gradient banners with entrance and exit timing queues.
- **Presenter Nametags (`TitleView.vue`)**: Dropdown title badges for displaying speaker names and professional roles.
- **Chroma-Key & Alpha Ingestion**: Windows are formatted with distinct background borders and transparent viewport layers, allowing streaming software to isolate graphics while minimizing edge artifacts.

The workstation can therefore separate an operator-facing control deck from the visible broadcast composition while both remain part of the same local production environment.

## Local Captioning Path

The transcription side is intentionally summarized here as part of the built artifact rather than repeated as a second architecture paper:

- The microphone's mono `AudioContext` buffer is downsampled to a **16 kHz** float stream.
- Samples are converted to signed 16-bit PCM integers (`convertFloat32ToInt16`) and streamed as binary WebSocket messages to `ws://localhost:8000/listen`.
- The FastAPI backend accumulates fixed-duration audio chunks and runs `model.transcribe()` through `asyncio.to_thread()`, moving blocking inference off the async event loop.
- Returned Whisper segments are filtered in `CaptionControl.vue`; accepted segments require `no_speech_prob <= 0.6`, `temperature <= 0.8`, and non-empty text before entering the caption queue.

At 16 kHz × 16-bit mono, the audio payload is approximately **32 kB/s (32,000 bytes/s)** before protocol overhead. That number is derived from the sample format, not measured as a runtime performance benchmark.

## Caption Rendering & Motion

When new transcription segments arrive from the backend, `CaptionsView.vue` computes the physical layout of active bubbles on screen:

- Using `getBoundingClientRect()`, each caption calculates its offset relative to previous elements.
- Bubble pop-in animations and vertical shifts are orchestrated using double-buffered `requestAnimationFrame` transitions.

This keeps caption layout and visual motion in the Electron/Vue renderer rather than coupling those responsibilities to the local inference service.

## Technical Stack

- **Desktop Shell**: Electron with `electron-acrylic-window` transparency and `qhotkeys` system bindings.
- **Frontend Layer**: Vue 3 (Composition API / `<script setup>`), Pinia state management, and Vite.
- **Audio Capture**: Web Audio API (`AudioContext`, `MediaStreamAudioSourceNode`, and the prototype's legacy `ScriptProcessorNode` path via `createScriptProcessor`).
- **Inference Engine**: Python, FastAPI, Uvicorn, and OpenAI Whisper.
- **Video Production**: OBS Studio window capture and transparent/chroma-key overlay compositing.
